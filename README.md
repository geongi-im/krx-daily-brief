# 일자 기반 시황 리포트 생성기

무료 공개 데이터(KRX, Yahoo Finance, 뉴스)만으로 코스피·삼성전자·SK하이닉스
중심의 시황 분석 HTML 리포트를 생성합니다. 기준일을 지정할 수도 있고, 생략하면
오늘로 잡혀 스케줄러로 매일 돌릴 수 있습니다. `--send`를 붙이면 생성한 리포트를
게시판에 올리고 텔레그램으로 알립니다.

리포트는 **"왜 올랐는가"를 단정하지 않습니다.** 가격·수급·기술 지표를 수치로 싣고,
같은 기간의 재료성 보도를 제목 그대로 인용하되 둘의 인과관계는 판정하지 않습니다.

---

## 설치

Python 3.9 이상이 필요합니다.

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

macOS·Linux는 `.venv\Scripts\python`을 `.venv/bin/python`으로 바꿔 읽으세요.
이하 모든 예시도 동일합니다.

### KRX 계정 설정 (필수)

pykrx 1.2.x는 KRX 정보데이터시스템 로그인을 요구합니다.
[data.krx.co.kr](https://data.krx.co.kr)에서 무료 회원가입 후, `.env.example`을
`.env`로 복사해 값을 채우세요.

```bash
copy .env.example .env
```

```
KRX_LOGIN_ID=아이디
KRX_LOGIN_PASSWORD=비밀번호
```

실행 시 python-dotenv로 자동으로 읽힙니다. 이미 같은 이름의 환경변수가 있으면
그쪽이 우선합니다. `.env`는 계정 정보이므로 공유·커밋하지 마세요.

pykrx(1.2.8)는 세션을 만들거나 만료 후 갱신할 때 `KRX_ID` / `KRX_PW`라는 이름을
직접 읽습니다(`website/comm/auth.py`의 `get_auth_session`). 이름을 바꿔 끼울 설정은
없어서, `main.py`가 위 값을 그 이름으로 옮겨 준 뒤 pykrx를 호출합니다. 따라서
`.env`에는 `KRX_LOGIN_*`만 적으면 됩니다.

### 설치 확인

```bash
.venv\Scripts\python main.py --check
```

`.env` 로드 → KRX 로그인 → KRX 데이터 → Yahoo 접속을 순서대로 점검합니다.
네 항목이 모두 OK면 준비가 끝난 것입니다.

## 사용법

```bash
.venv\Scripts\python main.py                  # 오늘 기준 리포트 생성
.venv\Scripts\python main.py --date 2026-08-07
```

| 옵션 | 설명 |
|---|---|
| `--date YYYY-MM-DD` | 기준 거래일. **생략하면 오늘**. `output\report_YYYYMMDD.html` 생성 |
| `--send` | 생성한 리포트를 게시판 API로 전송 (아래 참조). 기본은 전송하지 않음 |
| `--out 경로` | 출력 경로 직접 지정 |
| `--demo` | 내장 샘플로 렌더링만 확인. `output\_demo.html`에 저장되어 실제 리포트를 덮어쓰지 않음 (네트워크 불필요) |
| `--check` | 환경 자가진단 |

휴장일을 지정하면 데이터가 없어 실패합니다. 기준일은 거래일이어야 합니다.
`--date`를 생략할 때의 "오늘"은 **시스템 시간대 기준**이므로, 서버 TZ가
`Asia/Seoul`이 아니면 날짜가 하루 어긋납니다.

실행 경과는 콘솔과 `logs\YYYY-MM-DD_log.log`에 함께 기록됩니다. 스케줄러로 돌릴 때
실패 원인은 이 파일에서 확인하세요. 오래된 로그를 지우는 로직은 없습니다.

## 게시판 전송 (`--send`)

생성한 리포트를 MQWAY 게시판(`board-research`)에 올리고, 성공하면 게시물 링크를
텔레그램으로 안내합니다. `.env`에 아래 값이 필요합니다 (`.env.example` 참조).

| 변수 | 용도 |
|---|---|
| `BASE_URL` | 게시판 서버 주소. 끝의 `/api`는 코드가 붙이므로 `https://example.com`까지만 |
| `TELEGRAM_BOT_TOKEN` | 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 전송 성공 안내가 가는 운영 채팅방 |
| `TELEGRAM_CHAT_TEST_ID` | 전송 **실패** 알림이 가는 테스트 채팅방 |

전송되는 본문은 파일로 저장되는 완결 HTML 문서가 아니라 **조각**입니다. 게시판이
본문을 페이지 안에 그대로 삽입하므로 `<!DOCTYPE>`·`<head>`를 빼고, 리포트 CSS는
`.krx-brief` 하위로 범위를 좁혀 게시판 페이지가 덮이지 않게 합니다
(`render.py`의 `render_fragment()` / `_scope_css()`).

목록 카드 썸네일로 `img\thumbnail.png`를 매번 함께 올립니다. 파일이 없으면 경고만
남기고 썸네일 없이 진행합니다.

동작상 알아둘 점:

- **HTML 파일은 전송 전에 먼저 저장됩니다.** 전송이 실패해도 리포트는 남고
  `--send`로 다시 보낼 수 있습니다.
- **전송 실패해도 종료 코드는 0**입니다. 리포트 생성 자체는 성공했기 때문입니다.
  스케줄러가 전송 실패를 감지하게 하려면 이 부분을 바꿔야 합니다.
- 텔레그램은 **성공 시 운영 채널, 실패 시 테스트 채널**로 갑니다. 둘이 동시에
  가지는 않습니다.
- `BASE_URL`이 비어 있으면 전송을 건너뛰고 경고만 남깁니다.
- `--demo --send`는 차단됩니다. 샘플 데이터가 실서버에 게시글로 남으면 API로는
  지울 수 없기 때문입니다.

### 스케줄러 등록 (월~금)

`--date`를 생략하면 오늘로 잡히므로 명령에 날짜를 넣지 않아도 됩니다.

Linux — `crontab -e`

```cron
10 18 * * 1-5 cd /srv/krx-daily-brief && .venv/bin/python main.py --send >> logs/cron.log 2>&1
```

서버 TZ가 KST가 아니면 파일 맨 위에 `CRON_TZ=Asia/Seoul`을 넣으세요.

Windows

```powershell
schtasks /Create /TN "krx-daily-brief" /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 18:10 /TR "powershell -NoProfile -WindowStyle Hidden -Command \"Set-Location 'C:\경로\krx-daily-brief'; .\.venv\Scripts\python.exe main.py --send\""
```

장 마감(15:30) 이후면 되지만 수급 잠정치가 채워질 여유를 두어 18시대로 잡았습니다.

**공휴일 주의** — 월~금이어도 공휴일은 휴장이라 지수 조회가 실패하고 `exit 1`로
끝납니다. 전송 단계 전에 죽으므로 **텔레그램 알림이 가지 않습니다.** 그날의 실패는
로그에만 남습니다.

### 문제가 생기면

```bash
.venv\Scripts\python main.py --check
```

**KRX가 돌려준 오류 코드를 그대로 보여줍니다.** pykrx는 실패를 "자격 증명을
확인하세요"로만 알리고 이어지는 조회는 무관해 보이는 `KeyError`로 죽기 때문에,
원인을 구분하려면 이 진단이 필요합니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| `CD007: 패스워드 오류수에 의한 잠금` | 비밀번호 오류 누적으로 **계정 잠김** | `.env`만 고쳐서는 안 풀립니다. data.krx.co.kr에서 비밀번호를 재설정해 잠금을 해제한 뒤 `.env` 갱신 |
| `CD010: 비밀번호 변경 필요` | KRX 비밀번호 만료 | KRX에서 변경 후 `.env` 갱신 |
| `CD011: 중복 로그인` | 다른 세션이 열려 있음 | 다른 브라우저·기기에서 로그아웃 |
| 로그인은 OK인데 데이터 실패 | 네트워크·방화벽 또는 pykrx 버전 | 프록시 확인, `pip install -U pykrx` |

`--date` 실행이 "휴장일" 문구로 실패해도 실제 원인이 로그인일 수 있어, 실패 시
자동으로 로그인 상태를 확인해 원인을 함께 출력합니다.

## 폴더 구성

| 파일 | 용도 |
|---|---|
| `main.py` | 진입점 — CLI, `.env` 로드, KRX 로그인 진단, 자가진단(`--check`), 게시판 전송 |
| `collect.py` | 수집 — 설정 상수, `Bundle`, KRX·야후·뉴스 수집, 데모 데이터 |
| `render.py` | 렌더링 — 포맷 헬퍼, 자동 신호, HTML 템플릿, 전송용 조각, 독립성 가드 |
| `utils/api_util.py` | 게시판 API 클라이언트 (게시글 생성, 이미지 압축, 게시물 URL 조립) |
| `utils/telegram_util.py` | 텔레그램 전송 |
| `utils/logger_util.py` | 로거 — `logs/YYYY-MM-DD_log.log` |
| `requirements.txt` | 의존성 (pykrx, yfinance, pandas, requests, beautifulsoup4, Pillow) |
| `.env` / `.env.example` | KRX 계정·게시판 URL·텔레그램 토큰 (`.env`는 공유 금지) |
| `img/thumbnail.png` | 게시판 목록 카드에 쓰는 고정 썸네일 |
| `output/report_*.html` | 생성된 리포트 |
| `logs/*.log` | 실행 로그 (커밋 제외) |

의존 방향은 `main.py → render.py → collect.py` 한 방향입니다. 종목·티커·뉴스 필터
같은 설정 상수와 `Bundle`은 모두 `collect.py`에 있고, HTML·문구 수정은 `render.py`
안에서 끝납니다.

모든 리포트는 `output\`에 저장됩니다(없으면 자동 생성). `--out`으로 경로를
직접 지정한 경우만 예외입니다.

### 수정 후 확인 방법

```bash
.venv\Scripts\python main.py --demo              # 렌더링 전 구간 (네트워크 불필요)
.venv\Scripts\python main.py --date 2026-08-07   # 실데이터 수집까지 포함
```

`--demo`는 모든 섹션이 채워진 상태로 렌더링돼 표·문구 오류를 빠르게 잡습니다.
다만 **수집·계산 로직은 실데이터 실행으로만 검증됩니다.** 과거에 하드코딩 데이터로
정합성을 검사하는 오프라인 테스트를 두었으나, 주입한 숫자끼리의 자기 일관성만
확인하는 구조라 실제 버그(기여도 이중계산, 금리 스케일 오류)를 통과시켜 제거했습니다.

리포트 자체에 자기검증이 들어 있습니다. 기여도 합계가 지수 변동과 어긋나면
말미 '데이터 수집 내역'에 자동으로 기록되므로, 생성된 리포트를 열어 확인하세요.

### 뉴스 수집 방식

리포트는 **기준일 이후 기사를 절대 넣지 않습니다.** 그날 장 마감 시점에 알 수
없던 정보이기 때문이며, 이는 아래 설계 원칙 5와 직결됩니다.

| 소스 | 사용 조건 | 이유 |
|---|---|---|
| 네이버 금융 | 기준일이 **2일 이내**일 때만 | 최신순 목록만 제공해, 며칠 전 기사에 닿으려면 수십 페이지가 필요하고 페이지 순서도 시간순으로 떨어지지 않음 |
| 구글 뉴스 RSS | 항상 | `pubDate`(GMT→KST 변환)로 기준일 구간을 정확히 거를 수 있어 과거 날짜에도 안전 |

**시세 중계 기사는 제외합니다.** 검색 결과의 대부분은 `"삼성전자 주가, 8월 3일
239,500원 8.76% 하락 마감"` 같은 자동 생성 기사인데, 리포트가 이미 표로 싣는
수치를 문장으로 반복할 뿐이라 재료로 보기 어렵기 때문입니다. 판별은
`is_material_news()`가 담당합니다.

| 단계 | 역할 |
|---|---|
| `NEWS_HARD_DROP` | 연예·이벤트·커뮤니티 화제는 무조건 제외 (재료 단어가 우연히 겹치는 경우가 많아 최우선 적용) |
| `NEWS_KEEP_WORDS` | 실적·계약·IPO·자사주 등이 있으면 제목에 등락률이 섞여도 유지 |
| `NEWS_PRICE_DROP` | 위에 걸리지 않은 시세 중계·낚시성 제목 제외 |

실측 기준 36건 중 5건이 남았고, 제외 건수는 리포트 말미에 표기됩니다.
수집 범위는 `NEWS_LOOKBACK_DAYS`(기본 3일), 종목별 노출 건수는
`NEWS_PER_STOCK`(기본 6건)으로 조정합니다.

## 설계 원칙

1. **사실과 해석 구분** — 수치·보도 제목은 사실, 요약의 등락 요인은 규칙 기반 해석임을 명시
2. **미확보 데이터 투명성** — 수집 실패 항목은 숨기지 않고 사유와 함께 표기
3. **확률 제안 대신 실제 수치** — 규칙 기반으로 모든 국면을 담을 수 없으므로 시나리오
   확률을 싣지 않습니다. 대신 52주 고·저, 이동평균, 변동폭 백분위 같은 실측값을
   제시해 해석은 읽는 사람에게 맡깁니다
4. **한국 시장 색상 관례** — 상승=빨강, 하락=파랑
5. **리포트 독립성** — 각 리포트는 독립 문서. 다른 날짜 리포트를 언급·참조하지
   않으며, 렌더링 후 `validate_independence()` 검사로 강제

## 주의사항

- 뉴스는 **제목만** 싣고 인과는 판정하지 않습니다. 검색·목록 노출 순서에 따라
  중요한 기사가 빠지거나 주가와 무관한 기사가 실릴 수 있습니다.
- D램 현물가/계약가, 목표주가 컨센서스는 포함되지 않습니다 (유료 데이터).
- 52주 고·저나 변동성 백분위는 **과거 분포**일 뿐 앞으로의 범위를 보장하지 않습니다.
- 수급은 잠정치이며 확정치는 익영업일 공표됩니다.
