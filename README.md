# 일자 기반 시황 리포트 생성기

특정 거래일을 지정하면 무료 공개 데이터(KRX, Yahoo Finance, 뉴스)만으로
코스피·삼성전자·SK하이닉스 중심의 시황 분석 HTML 리포트를 생성합니다.

리포트는 **"왜 올랐는가"를 단정하지 않습니다.** 가격·수급·기술 지표를 수치로 싣고,
같은 기간의 재료성 보도를 제목 그대로 인용하되 둘의 인과관계는 판정하지 않습니다.

---

## 설치

Python 3.9 이상이 필요합니다.

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

macOS·Linux는 `.venv\Scripts\python`을 `.venv/bin/python`으로 바꿔 읽으세요.
이하 모든 예시도 동일합니다.

### KRX 계정 설정 (필수)

pykrx 1.2.x는 KRX 정보데이터시스템 로그인을 요구합니다.
[data.krx.co.kr](https://data.krx.co.kr)에서 무료 회원가입 후, `.env.example`을
`.env`로 복사해 값을 채우세요.

```bash
copy .env.example .env
```

```
KRX_ID=아이디
KRX_PW=비밀번호
```

실행 시 자동으로 읽힙니다(별도 패키지 불필요). 이미 같은 이름의 환경변수가 있으면
그쪽이 우선합니다. `.env`는 계정 정보이므로 공유·커밋하지 마세요.

### 설치 확인

```bash
.venv\Scripts\python main.py --check
```

`.env` 로드 → KRX 로그인 → KRX 데이터 → Yahoo 접속을 순서대로 점검합니다.
네 항목이 모두 OK면 준비가 끝난 것입니다.

## 사용법

```bash
.venv\Scripts\python main.py --date 2026-08-07
```

| 옵션 | 설명 |
|---|---|
| `--date YYYY-MM-DD` | 기준 거래일. `output\report_YYYYMMDD.html` 생성 |
| `--out 경로` | 출력 경로 직접 지정 |
| `--demo` | 내장 샘플로 렌더링만 확인. `output\_demo.html`에 저장되어 실제 리포트를 덮어쓰지 않음 (네트워크 불필요) |
| `--check` | 환경 자가진단 |

휴장일을 지정하면 데이터가 없어 실패합니다. 기준일은 거래일이어야 합니다.

### 문제가 생기면

```bash
.venv\Scripts\python main.py --check
```

**KRX가 돌려준 오류 코드를 그대로 보여줍니다.** pykrx는 실패를 "자격 증명을
확인하세요"로만 알리고 이어지는 조회는 무관해 보이는 `KeyError`로 죽기 때문에,
원인을 구분하려면 이 진단이 필요합니다.

| 증상 | 원인 | 조치 |
|---|---|---|
| `CD007: 패스워드 오류수에 의한 잠금` | 비밀번호 오류 누적으로 **계정 잠김** | `.env`만 고쳐서는 안 풀립니다. data.krx.co.kr에서 비밀번호를 재설정해 잠금을 해제한 뒤 `.env` 갱신 |
| `CD010: 비밀번호 변경 필요` | KRX 비밀번호 만료 | KRX에서 변경 후 `.env` 갱신 |
| `CD011: 중복 로그인` | 다른 세션이 열려 있음 | 다른 브라우저·기기에서 로그아웃 |
| 로그인은 OK인데 데이터 실패 | 네트워크·방화벽 또는 pykrx 버전 | 프록시 확인, `pip install -U pykrx` |

`--date` 실행이 "휴장일" 문구로 실패해도 실제 원인이 로그인일 수 있어, 실패 시
자동으로 로그인 상태를 확인해 원인을 함께 출력합니다.

## 폴더 구성

| 파일 | 용도 |
|---|---|
| `main.py` | 진입점 — CLI, `.env` 로드, KRX 로그인 진단, 자가진단(`--check`) |
| `collect.py` | 수집 — 설정 상수, `Bundle`, KRX·야후·뉴스 수집, 데모 데이터 |
| `render.py` | 렌더링 — 포맷 헬퍼, 자동 신호, HTML 템플릿, 독립성 가드 |
| `requirements.txt` | 의존성 (pykrx, yfinance, pandas, requests, beautifulsoup4) |
| `.env` / `.env.example` | KRX 계정 (`.env`는 공유 금지) |
| `output/report_*.html` | 생성된 리포트 |

의존 방향은 `main.py → render.py → collect.py` 한 방향입니다. 종목·티커·뉴스 필터
같은 설정 상수와 `Bundle`은 모두 `collect.py`에 있고, HTML·문구 수정은 `render.py`
안에서 끝납니다.

모든 리포트는 `output\`에 저장됩니다(없으면 자동 생성). `--out`으로 경로를
직접 지정한 경우만 예외입니다.

### 수정 후 확인 방법

```bash
.venv\Scripts\python main.py --demo              # 렌더링 전 구간 (네트워크 불필요)
.venv\Scripts\python main.py --date 2026-08-07   # 실데이터 수집까지 포함
```

`--demo`는 모든 섹션이 채워진 상태로 렌더링돼 표·문구 오류를 빠르게 잡습니다.
다만 **수집·계산 로직은 실데이터 실행으로만 검증됩니다.** 과거에 하드코딩 데이터로
정합성을 검사하는 오프라인 테스트를 두었으나, 주입한 숫자끼리의 자기 일관성만
확인하는 구조라 실제 버그(기여도 이중계산, 금리 스케일 오류)를 통과시켜 제거했습니다.

리포트 자체에 자기검증이 들어 있습니다. 기여도 합계가 지수 변동과 어긋나면
말미 '데이터 수집 내역'에 자동으로 기록되므로, 생성된 리포트를 열어 확인하세요.

## 리포트 구성

| 섹션 | 데이터 소스 |
|---|---|
| 요약 (등락 요인) | KRX 시세 |
| 1. 최근 5거래일 등락 | KRX 시세 |
| 2. 지수 기여도 분해 (상승·하락 기여 상위) | KRX 시가총액 |
| 3. 일중 가격 흐름 (OHLC, 종가 위치) | KRX 시세 |
| 4. 시장 폭 및 업종별 등락 | KRX |
| 5. 투자자별 수급 (당일·전일·10일 누적·연속일수·종목별) | KRX |
| 6~7. 종목 상세 (기술지표·PER/PBR·배당·외국인 지분율) | KRX |
| 8. 미국 증시 및 거시지표 (환율·VIX·금리·달러인덱스·유가) | Yahoo Finance |
| 9. 주요 재료 및 관련 보도 (제목·일시·출처·링크) | 네이버 금융 · 구글 뉴스 RSS |
| 10. 기술적 위치 및 변동성 지표 (52주 고·저, 이동평균, 변동폭 백분위) | KRX 시세 기반 자체 산출 |
| 부록. 데이터 수집 내역 (미수집 항목·수집 기준) | 자동 기록 |

### 뉴스 수집 방식

리포트는 **기준일 이후 기사를 절대 넣지 않습니다.** 그날 장 마감 시점에 알 수
없던 정보이기 때문이며, 이는 아래 설계 원칙 5와 직결됩니다.

| 소스 | 사용 조건 | 이유 |
|---|---|---|
| 네이버 금융 | 기준일이 **2일 이내**일 때만 | 최신순 목록만 제공해, 며칠 전 기사에 닿으려면 수십 페이지가 필요하고 페이지 순서도 시간순으로 떨어지지 않음 |
| 구글 뉴스 RSS | 항상 | `pubDate`(GMT→KST 변환)로 기준일 구간을 정확히 거를 수 있어 과거 날짜에도 안전 |

**시세 중계 기사는 제외합니다.** 검색 결과의 대부분은 `"삼성전자 주가, 8월 3일
239,500원 8.76% 하락 마감"` 같은 자동 생성 기사인데, 리포트가 이미 표로 싣는
수치를 문장으로 반복할 뿐이라 재료로 보기 어렵기 때문입니다. 판별은
`is_material_news()`가 담당합니다.

| 단계 | 역할 |
|---|---|
| `NEWS_HARD_DROP` | 연예·이벤트·커뮤니티 화제는 무조건 제외 (재료 단어가 우연히 겹치는 경우가 많아 최우선 적용) |
| `NEWS_KEEP_WORDS` | 실적·계약·IPO·자사주 등이 있으면 제목에 등락률이 섞여도 유지 |
| `NEWS_PRICE_DROP` | 위에 걸리지 않은 시세 중계·낚시성 제목 제외 |

실측 기준 36건 중 5건이 남았고, 제외 건수는 리포트 말미에 표기됩니다.
수집 범위는 `NEWS_LOOKBACK_DAYS`(기본 3일), 종목별 노출 건수는
`NEWS_PER_STOCK`(기본 6건)으로 조정합니다.

## 설계 원칙

1. **사실과 해석 구분** — 수치·보도 제목은 사실, 요약의 등락 요인은 규칙 기반 해석임을 명시
2. **미확보 데이터 투명성** — 수집 실패 항목은 숨기지 않고 사유와 함께 표기
3. **확률 제안 대신 실제 수치** — 규칙 기반으로 모든 국면을 담을 수 없으므로 시나리오
   확률을 싣지 않습니다. 대신 52주 고·저, 이동평균, 변동폭 백분위 같은 실측값을
   제시해 해석은 읽는 사람에게 맡깁니다
4. **한국 시장 색상 관례** — 상승=빨강, 하락=파랑
5. **리포트 독립성** — 각 리포트는 독립 문서. 다른 날짜 리포트를 언급·참조하지
   않으며, 렌더링 후 `validate_independence()` 검사로 강제

## 주의사항

- 뉴스는 **제목만** 싣고 인과는 판정하지 않습니다. 검색·목록 노출 순서에 따라
  중요한 기사가 빠지거나 주가와 무관한 기사가 실릴 수 있습니다.
- D램 현물가/계약가, 목표주가 컨센서스는 포함되지 않습니다 (유료 데이터).
- 52주 고·저나 변동성 백분위는 **과거 분포**일 뿐 앞으로의 범위를 보장하지 않습니다.
- 수급은 잠정치이며 확정치는 익영업일 공표됩니다.
- 환율(`KRW=X`)은 실시간 스팟 시세라 장 종료 후에도 갱신됩니다. 같은 기준일로
  다시 실행하면 수치와 등락 방향이 달라질 수 있습니다.
- 정보 제공 및 학습 목적이며, 투자 권유가 아닙니다.
